# Мовна політика документації

Уся документація проекту ведеться виключно українською мовою.

Обсяг охоплює:

- README-файли;
- записи CHANGELOG;
- файли під `docs/`;
- операторські runbook-и;
- архітектурні/design-нотатки;
- документаційні коментарі (не загальні inline-коментарі в коді);
- описи PR/issue, коли вони функціонують як формальна документація проекту.

Лише технічні терміни лишаються англійською, в оригінальній формі, без
перекладу:

- назви команд, CLI-прапорці та параметри;
- ідентифікатори коду (назви функцій, змінних, файлів і шляхів);
- назви продуктів, технологій і протоколів;
- ключі конфігурації, назви exit-кодів та назви API/полів.

Не перекладай власні назви, ключі конфігурації, exit-коди чи назви
API/параметрів лише заради узгодженості з рештою тексту.

Це правило регулює документацію проекту. Воно саме по собі не змінює
наявну практику для inline-коментарів у коді поза документаційними
файлами.

Дотримуйся повної орфографічної коректності української мови, включно з
обов'язковими діакритичними знаками та наголосами — ніколи не заміняй їх
ASCII-еквівалентами.
