# Manual Run Console UX Contract

Цей документ фіксує цільовий зовнішній вигляд консолі BRAVO Archive при **ручному інтерактивному запуску**. Це UI contract для майбутньої реалізації: структура, порядок блоків, стани, ключові поля та операторські пояснення мають залишатися стабільними, навіть якщо внутрішня реалізація runtime змінюється.

## Загальні правила

- Цей формат використовується лише для ручного інтерактивного запуску.
- Scheduled/non-interactive запуск не повинен чекати натискання клавіші.
- Header показує продукт, версію, установу, hostname та режим запуску.
- Основні етапи показуються послідовно у форматі `[N/M]`.
- Кількість етапів `M` формується динамічно за реально активними операціями.
- Стани етапів: `OK`, `WARNING`, `ERROR`, `SKIPPED`.
- Для завершеного етапу показується його duration.
- Для `WARNING` та `ERROR` під рядком етапу показується коротка операторська `Причина:`.
- Для `SKIPPED` коротка причина показується лише коли вона неочевидна; для групи пропущених етапів допускається одна загальна причина після групи.
- Технічний stack trace, exception details, command line, stdout/stderr та інші низькорівневі деталі залишаються в логах.
- Після етапів завжди виводиться один підсумковий блок `РЕЗУЛЬТАТ`.
- Підсумковий блок не дублюється для кожного архіву.
- Для всіх локальних архівів показуються component name, розмір і повний шлях.
- Повний шлях архіву виводиться окремим рядком під component, щоб не залежати від ширини старих Windows console hosts.
- При невдалому створенні конкретного архіву показується `ERROR` та коротке пояснення `Архів не створено`.
- `Створено архівів: X з Y` показує кількість фактично створених локальних архівів відносно запланованих.
- `Загальний розмір` — сума розмірів лише фактично створених локальних архівів.
- Summary показує формальний BRAVO exit code; native exit code зовнішньої утиліти показується окремо і не замінює BRAVO exit code.
- Будь-який native exit code зовнішньої утиліти, показаний оператору, обов'язково супроводжується коротким україномовним поясненням.
- ASCII-роздільники `=` та `-` використовуються навмисно для сумісності зі старими Windows console hosts.
- Після `РЕЗУЛЬТАТ` ручний запуск завершується паузою: `Натисніть будь-яку клавішу для закриття...`.

## Формат етапу

Базовий формат:

```text
[N/M] Назва етапу ............................ STATUS   HH:mm:ss
```

Для коротких етапів duration може бути `mm:ss`; для довгих — `HH:mm:ss`.

Помилка:

```text
[4/5] Архівація BRAVOEXCH .................... ERROR    00:07
      Причина: 7-Zip код 2 — критична помилка
      Деталі:  Не вдалося створити архів BRAVOEXCH
```

Попередження:

```text
[3/5] Архівація BLOG ......................... WARNING  01:22
      Причина: Архів створено, але очищення старого архіву не виконано
```

Пропущений етап:

```text
[5/5] Передача SFTP .......................... SKIPPED

      Передачу SFTP пропущено через помилку локальної архівації.
```

## Native exit codes зовнішніх інструментів

Console layer повинен мати єдиний механізм перетворення native exit code зовнішньої утиліти на операторське пояснення. Робоча назва API:

```text
Get-BRAVOToolExitCodeDescription
```

Для кожного підтримуваного tool зберігаються:

- tool name;
- native numeric exit code;
- canonical technical name, якщо він є;
- severity (`success`, `warning`, `error`);
- коротке україномовне пояснення для оператора.

BRAVO exit code та native tool exit code не змішуються.

Приклад для 7-Zip:

```text
0    Успішно
1    Попередження — операцію виконано не повністю
2    Критична помилка
7    Помилка параметрів командного рядка
8    Недостатньо пам'яті
255  Операцію перервано користувачем
```

Наприклад:

```text
[2/5] Архівація MODEL ........................ ERROR    03:27
      Причина: 7-Zip код 8 — недостатньо пам'яті
```

У summary це відображається окремими полями:

```text
Код завершення:   40 — LocalArchiveFailed
Причина:          Не вдалося створити архів MODEL
Інструмент:       7-Zip
Код інструменту:  8 — недостатньо пам'яті
```

Повний exception, stderr/stdout та command line залишаються лише в логах і не повинні засмічувати операторський console output.

## Семантика `РЕЗУЛЬТАТ`

`Статус` — людський підсумок верхнього рівня (`УСПІШНО`, `ПОПЕРЕДЖЕННЯ`, `ПОМИЛКА`, `ПРОПУЩЕНО`).

`Код завершення` — числовий код і canonical name з `BRAVO.ExitCodes`, без паралельної класифікації помилок у console layer.

`Причина` — одна коротка операторська причина головного failure/warning. Вона не повинна бути stack trace або необробленим exception text.

`Інструмент` / `Код інструменту` — показуються лише коли головний результат безпосередньо спричинений зовнішнім tool. Native code завжди супроводжується операторським поясненням.

`Початок` / `Завершення` — локальний wall-clock timestamp у форматі `dd.MM.yyyy HH:mm:ss`.

`Тривалість` — wall-clock duration поточного runtime run у форматі `HH:mm:ss`.

`Створено архівів` — тільки локальні archive artifacts, не SFTP/SMB copies.

`Загальний розмір` — сумарний фізичний розмір створених archive artifacts із human-readable автоматичним масштабуванням `KB/MB/GB/TB`.

`Архіви` — список усіх запланованих archive components у стабільному порядку. Успішний component показує розмір і повний шлях окремим рядком; невдалий component показує `ERROR` і коротке пояснення без вигаданого шляху.

## Колір

Для ручного інтерактивного запуску колір може використовуватися тільки як додатковий visual aid:

- `OK` — зелений;
- `WARNING` — жовтий;
- `ERROR` — червоний;
- `SKIPPED` — сірий/темно-жовтий;
- основний текст — стандартний колір консолі.

Текстовий статус завжди обов'язковий: колір не може бути єдиним носієм змісту. При redirect output або scheduled/non-interactive запуску ANSI/console coloring не повинно потрапляти у файл/лог.

## Віддалений моніторинг / FEAT-003

До фактичної реалізації FEAT-003 у консолі **не показуються** placeholders `Telemetry`, `Server ID`, `Event ID` або `DISABLED`.

Коли Remote Fleet Telemetry буде реалізовано, telemetry додається **тільки наприкінці блоку `РЕЗУЛЬТАТ`, після списку архівів і перед фінальним роздільником**:

```text
Віддалений моніторинг:
  Telemetry:     SENT
  Server ID:     00702245-a63df820...
  Event ID:      ce70abae-c3b7-...
```

Telemetry status є інформаційним підблоком і не змінює BRAVO runtime exit code. Недоступність gateway не повинна перетворювати успішний backup на failed backup.

## Критерії реалізації

- [ ] Header відповідає цьому contract, містить режим запуску і не містить секретів.
- [ ] `[N/M]` формується динамічно та відображає лише реально заплановані етапи.
- [ ] Для кожного завершеного етапу показується один фінальний `OK` / `WARNING` / `ERROR` / `SKIPPED`.
- [ ] Для завершених `OK` / `WARNING` / `ERROR` етапів показується duration.
- [ ] `WARNING` та `ERROR` мають коротку операторську `Причина:`.
- [ ] Технічні stack trace/stdout/stderr не виводяться в normal console UX.
- [ ] Native tool exit code не показується без україномовного пояснення.
- [ ] BRAVO exit code та native tool exit code не змішуються.
- [ ] Є рівно один блок `РЕЗУЛЬТАТ` на один runtime run.
- [ ] У summary є `Початок`, `Завершення` та `Тривалість`.
- [ ] `Створено архівів: X з Y` обчислюється з фактичних artifacts.
- [ ] `Загальний розмір` обчислюється з фактичних artifacts.
- [ ] Список `Архіви` містить усі заплановані archive components і повні шляхи успішних artifacts.
- [ ] Повний шлях archive artifact виводиться окремим рядком під component.
- [ ] Часткова помилка не приховує успішно створені artifacts.
- [ ] Console `Код завершення` збігається з process exit code.
- [ ] Manual run чекає клавішу тільки після повного виводу `РЕЗУЛЬТАТ`.
- [ ] Scheduled/non-interactive run не чекає клавішу.
- [ ] Telemetry block відсутній до реалізації FEAT-003.
- [ ] Після реалізації FEAT-003 telemetry block з'являється тільки в кінці `РЕЗУЛЬТАТ` і не впливає на runtime exit code.
